# Проверки

```bash
cd tests
npm install            # playwright-core и библиотеки тех же версий, что в приложении
node vendor.js         # разложить библиотеки в tests/vendor
python3 fixtures/make_books.py   # собрать книги
python3 build.py       # собрать локальную копию приложения
node run.js            # прогнать всё; node run.js graph — только один набор
```

Коротко: `npm run setup` делает первые четыре шага, `npm test` — последние два.

## Как это устроено

**Книги строятся, а не лежат в репозитории.** `fixtures/make_books.py` пишет
голый OOXML: только так получаются вещи, которых обычные библиотеки не дают, —
скрытые имена `hidden="1"`, ссылки `#REF!`, листы `veryHidden`, запросы Power
Query в контейнере DataMashup. Данные внутри выдуманные: настоящие рабочие
книги в репозиторий класть нельзя, а проверкам нужна не правда жизни, а
конкретные признаки.

| книга | что в ней заложено |
|---|---|
| `clean.xlsx` | опрятная книга без единой находки — точка отсчёта |
| `messy.xlsm` | 15 правил качества: скрытые имена четырёх происхождений, `#REF!`, `#ДЕЛ/0!`, `#Н/Д`, листы `hidden` и `veryHidden`, ручной пересчёт, VBA, внешняя книга на локальном диске, порванная формульная колонка, лист-сирота |
| `pq.xlsx` | восемь запросов Power Query: источники пяти видов и цепочка запрос → запрос |
| `v1.xlsx`, `v2.xlsx` | пара версий: лист переименован, имя убрано, формула изменена, лист добавлен |
| `huge.xlsx` | лист в 42 МБ распакованного XML — заведомо выше потолка в 40 МБ, с ошибками `#REF!` в каждой строке. Файл весит 5 МБ, собирается секунды: он намеренно однообразен |

**Приложение собирается локально.** REX грузит библиотеки с jsDelivr; в
проверках выходить в сеть нельзя — прогон становится зависимым от чужого
сервиса. `build.py` переписывает ссылки на `tests/vendor` и **сверяет каждый
файл с `integrity` из разметки**: не совпала сумма sha384 — сборка падает, а
не подсовывает проверкам другой код.

**Набор — это файл в `suites/`,** экспортирующий функцию и возвращающий число
провалов. Обвязка `harness.js` держит на себе то, в чём легко ошибиться
поодиночке: ожидание конца разбора (а не «подождём три секунды»), отсев
сообщений, которые пишет сам Chromium, и единый счёт.

| набор | о чём |
|---|---|
| `smoke` | разбор доходит до конца, все разделы открываются |
| `quality` | правила срабатывают на запущенной книге **и молчат на опрятной** |
| `cleanup` | имена разобраны по происхождению, макрос собран под выбор и ничего не делает молча |
| `graph` | холст, фильтры, выбор объекта, цвет связей по направлению |
| `pq` | запросы, источники по видам, цепочки |
| `columns` | подмена протянутой формулы находится |
| `versions` | область просмотра, сравнение, различия на графе, удаление книги |
| `interface` | подсказки (i), положение заголовков, вёрстка индекса здоровья, точки у значков |
| `landing` | `index.html`: ссылки ведут на тот файл, что лежит рядом; вёрстка от 1450 до 360 px |
| `convert` | конвертер форматов: обход папки, отбор, запись файла и чтение его обратно — на папке, которая живёт в памяти |
| `huge` | лист сверх потолка разбора: помечен, счётчики пусты, и об этом сказано на обзоре, в таблице листов, на «Качестве данных» и в отчёте |

## Что проверки стоят

Прогон занимает около 45 секунд. Ошибки они находят: `graph` при первом же
запуске показал, что выбранный объект встаёт на 21 px выше центра, когда
приближать не понадобилось, — cytoscape центрировал рамку с подписью вместо
самого узла.

## Если что-то упало

Сначала посмотрите, не устарела ли сама проверка: несколько раз правка была
осознанной, а набор сторожил отменённое поведение. Признак — набор падает на
нетронутом коде сразу после правки в соседней области.
